## ⚡ Core Idea
- Learning rate controls update size: too large can diverge/oscillate; too small makes progress slow.
- Track training and validation curves separately; falling train loss with rising validation loss suggests overfitting.
- Schedulers alter LR at a defined interval; know whether the scheduler steps per batch or per epoch.
- Warmup, cosine decay, and plateau-based reduction are common schedules; select based on validation behavior.

## ⚠️ 3 Contest Traps
1. Calling `ReduceLROnPlateau.step()` without the monitored validation metric defeats its purpose.
2. Calling an epoch scheduler every minibatch advances the schedule too quickly.
3. Comparing LR across different batch sizes without accounting for changed optimization dynamics is misleading.

## 💻 Copy-Paste Contest Starter Code
```python
import torch
from torch import nn
model = nn.Linear(16, 2)
opt = torch.optim.AdamW(model.parameters(), lr=3e-3)
sched = torch.optim.lr_scheduler.ReduceLROnPlateau(
    opt, mode="min", factor=0.5, patience=2)
x, y = torch.randn(128, 16), torch.randint(0, 2, (128,))
xv, yv = torch.randn(32, 16), torch.randint(0, 2, (32,))
for epoch in range(10):
    model.train(); opt.zero_grad(set_to_none=True)
    loss = nn.functional.cross_entropy(model(x), y)
    loss.backward(); opt.step()
    model.eval()
    with torch.no_grad():
        val_loss = nn.functional.cross_entropy(model(xv), yv).item()
    sched.step(val_loss)
    print(epoch, opt.param_groups[0]["lr"])
```

## ✅ Quick Check
<details><summary>Q1 — A learning rate that is too large often causes?</summary>

A) Divergence/oscillation B) Guaranteed generalization C) Zero gradients always

**Answer:** A. Updates can overshoot minima or become unstable.
</details>

<details><summary>Q2 — ReduceLROnPlateau should monitor?</summary>

A) Validation metric B) Parameter values C) Class IDs

**Answer:** A. It reduces LR when the monitored metric stops improving.
</details>

<details><summary>Q3 — An epoch scheduler called per minibatch usually?</summary>

A) Decays too quickly B) Has no effect C) Runs too slowly

**Answer:** A. The schedule advances many times per epoch instead of once.
</details>
