## ⚡ Core Idea
- `Tensor` stores data; `nn.Module` defines models; optimizers update parameters.
- Training loop: clear gradients → forward → loss → backward → optimizer step.
- For multiclass tasks, `CrossEntropyLoss` expects raw logits and integer `torch.long` labels.
- Save/load `state_dict()`; recreate the model architecture before loading weights.

## ⚠️ 3 Contest Traps
1. Forgetting `zero_grad()` accumulates gradients across batches.
2. Applying softmax before `CrossEntropyLoss` double-normalizes logits.
3. Forgetting `model.eval()` leaves dropout active and BatchNorm updating during validation.

## 💻 Copy-Paste Contest Starter Code
```python
import torch
from torch import nn
x = torch.randn(32, 10)
y = torch.randint(0, 3, (32,))
model = nn.Sequential(nn.Linear(10, 32), nn.ReLU(), nn.Linear(32, 3))
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)
model.train()
opt.zero_grad(set_to_none=True)
loss = nn.functional.cross_entropy(model(x), y)
loss.backward()
opt.step()
model.eval()
with torch.no_grad():
    pred = model(x).argmax(dim=1)
torch.save(model.state_dict(), "model.pt")
```

## ✅ Quick Check
<details><summary>Q1 — What goes into CrossEntropyLoss?</summary>

A) Softmax probabilities B) Raw logits C) Argmax labels

**Answer:** B. CrossEntropyLoss applies log-softmax internally.
</details>

<details><summary>Q2 — Correct training order?</summary>

A) step → backward → zero_grad B) zero_grad → forward/loss → backward → step C) eval → step

**Answer:** B. Clear old gradients before calculating the new batch's gradients.
</details>

<details><summary>Q3 — What disables dropout at inference?</summary>

A) no_grad alone B) model.eval() C) zero_grad

**Answer:** B. no_grad disables autograd; eval changes module behavior.
</details>
