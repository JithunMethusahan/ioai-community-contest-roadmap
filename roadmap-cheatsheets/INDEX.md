## Repository architecture and UI integration

- `/roadmap`: `src/pages/Roadmap.tsx` renders contest-task cards from `src/data/referenceSections.json` via `src/data/referenceTasks.ts`. This is JSON-backed, not a database.
- `/theory`: `src/pages/Theory.tsx` reads its topic hierarchy from `src/data/theory.ts`; lesson bodies are loaded from `src/theory/*.mdx` using `import.meta.glob`. This is TypeScript-config + MDX, not a database.
- No dedicated `/problem-bank` route exists in the current router; contest tasks are listed in `src/data/contests.json` and `src/data/beginner-contests.json`, with editorial MDX in `src/solutions/round-*/`.
- This phase stores cheat sheets here as Markdown and intentionally does not alter existing UI features. To wire them in, add a dedicated route/component, load `roadmap-cheatsheets/*.md` with a Vite glob (or generate a manifest at build time), render Markdown with the site's existing renderer, and link each theory topic to its numbered sheet. Do not merge them into `src/theory/*.mdx` until the route/ID design is decided.

## AICC matching policy

Only tasks present in the repository's contest JSON are eligible. Each sheet links a real AICC task/editorial only when the title/category makes a defensible match; otherwise it says `TODO: Match AICC task`. Never infer that a task uses a specific model/technique from its category alone.
