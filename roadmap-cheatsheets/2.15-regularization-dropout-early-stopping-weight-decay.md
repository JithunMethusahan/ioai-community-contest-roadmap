## ⚡ Core Idea
- Dropout randomly zeros activations during training; `model.eval()` disables it for inference.
- AdamW decouples weight decay from Adam's adaptive gradient update.
- Early stopping monitors validation performance and restores the best checkpoint, not the final epoch.
- Regularization should improve held-out performance; excessive strength causes underfitting.

## ⚠️ 3 Contest Traps
1. Forgetting `model.eval()` leaves dropout active and BatchNorm updating at inference.
2. Saving only the final epoch loses the best validation checkpoint.
3. Applying strong decay indiscriminately to biases/normalization parameters can hurt.

import copy, torch
from torch import nn
model = nn.Sequential(nn.Linear(20, 64), nn.ReLU(),
                      nn.Dropout(0.25), nn.Linear(64, 2))
opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)
best, best_loss, stale, patience = None, float("inf"), 0, 3

## ✅ Quick Check
<details><summary>Q1 — Which call disables dropout behavior?</summary>

A) model.eval() B) loss.backward() C) optimizer.zero_grad()

**Answer:** A. Evaluation mode disables dropout and freezes BatchNorm running-stat updates.
</details>

<details><summary>Q2 — AdamW weight decay is?</summary>

A) Decoupled from adaptive update B) Dropout C) Label smoothing

**Answer:** A. AdamW applies decoupled weight decay.
</details>

<details><summary>Q3 — Early stopping should restore?</summary>

A) Last epoch B) Best validation checkpoint C) Random checkpoint

**Answer:** B. The selected model is the best held-out validation state.
</details>
